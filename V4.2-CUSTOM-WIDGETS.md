# Kiwi Calendar 4.2 — Custom widgets

This is a source update **on top of v4.1**, not a stand-alone APK or a new container registry image.

## Sports scoreboard
- ESPN-hosted team logos are returned by `/api/sports/teams` and `/api/scores` when the provider supplies them. Bad/missing logos fall back to abbreviations on the web and Android.
- Each card places both teams opposite a prominent central score. LIVE, FINAL, and SAVED are visually distinct.
- The v4.1 rolling **seven-day limit** is still enforced by the server, Android, and web client. Games from earlier than 168 hours ago and future fixtures aren't shown as recent scores.
- Team names, league, result, and details remain readable even when logos fail to download.
- The ESPN site API is unofficial, so logos/scores depend on that provider and an internet connection.

## Weather display
- The web dashboard has original vector weather condition art, a large temperature, high/low, rain, humidity, wind, six upcoming hours, and tomorrow's forecast.
- The Android photo/sleep screen has a high-contrast atmospheric weather card showing conditions, feels-like, high/low, rain, humidity, wind and six forecast hours.
- The sleep-screen card uses fixed, high-contrast colors in both system themes so photos can't wash out the text.
- Location and unit settings still control the actual API request. Stale replies for the wrong location are discarded.

## Apply to your v4.1 repository

**GitHub:** On your existing feature branch, copy the files from `kiwi-calendar-v4.2-overlay.zip` into the root of your checkout, replacing matching files. Commit and push. Do not delete other files or your existing `android/app/src/main/res/font` folder.

**Command line:** Alternatively apply `kiwi-calendar-v4.2.patch` from the root of a clean v4.1 checkout:

```sh
git apply --check kiwi-calendar-v4.2.patch
git apply kiwi-calendar-v4.2.patch
```

**Docker Desktop (Windows):** Rebuild in your existing project folder:

```powershell
docker compose up -d --build --force-recreate
```

This preserves named volumes. **Do not run `docker compose down -v`.** Your existing login token remains stored in your existing volume.

**Android:** Rebuild through the Android GitHub Actions workflow and install the newly signed APK. Upgrading an installed app requires the same signing key as your existing APK.
